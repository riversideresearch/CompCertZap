## CI/CD & Deployment

**Hosting:**
- Not applicable - CompCert is a build tool, not a hosted service

**Build Tools:**
- No external CI detected
- Relies on Make-based build system (`Makefile`, `Makefile.extr`)
- Build stages:
  1. Proof compilation: `make proof` (coqc on all `.v` files)
  2. Extraction: `make extraction` (Coq extraction to OCaml)
  3. Compiler binary: `make ccomp` (OCamlopt linking)
  4. Runtime library: `make runtime` (C assembly and helpers)
  5. Export tools: `make clightgen` (C AST generator), `make vcomp` (Cminor importer)

## External Tool Chain Integration

**C Preprocessor:**
- Default: `gcc -E` (configurable in Makefile.config)
- Configured via: `CPREPRO`, `CPREPRO_OPTIONS`
- Used for: Preprocessing `.c` files to `.i`

**Assembler:**
- Default: `gcc -c` (x86-64 assembly to object files)
- Configured via: `CASM`, `CASM_OPTIONS`
- Used for: Converting generated `.s` (and hand-written `.S`) to `.o` objects

**Linker:**
- Default: `gcc` (final executable linking)
- Configured via: `CLINKER`, `CLINKER_OPTIONS`
- Used for: Linking `.o` object files into final binary

**Runtime Assembler:**
- Default: `gcc -c` (separate from general assembler)
- Configured via: `CASMRUNTIME`, separate from `CASM`
- Used for: Building runtime library assembly (`.S` files in `runtime/` directory)

**Archiver:**
- Tool: `ar rcs`
- Used for: Creating static library `libcompcert.a` from runtime object files

## Environment Configuration

**Required env vars:**
- `COQBIN` - Path to Coq executables (coqc, coqdep, coqtop, coqchk)
- `MENHIR_DIR` - Path to Menhir library (typically OPAM managed)
- `COMPCERT_CONFIG` - Optional override for config file location (checked in Configuration.ml)

**Build-time vars (Makefile.config):**
- `PREFIX` - Installation prefix (/usr/local default)
- `ARCH` - Target architecture (x86, arm, riscv, powerpc, aarch64)
- `MODEL` - Bit width/model variant (64, 32, ppc64, e5500, etc.)
- `BITSIZE` - 64 or 32
- `ABI` - Application Binary Interface (standard or hardfloat)
- `SYSTEM` - Operating system (linux, cygwin, macos, etc.)
- `ENDIANNESS` - little or big

**Optional feature env vars:**
- `LIBRARY_FLOCQ` - Use local (default) or system Flocq
- `LIBRARY_MENHIRLIB` - Use local (default) or system MenhirLib
- `OCAML_NATIVE_COMP` - Native code compilation support (true/false)
- `OCAML_OPT_COMP` - Use optimized compilers (ocamlopt.opt) if available
- `INSTALL_COQDEV` - Install Coq development files (false by default)
- `CLIGHTGEN` - Build C AST generator tool (false by default)

- Not applicable - CompCert stores no secrets

## Parser Integration Points

**C Parser:**
- Menhir-based LR parser (`cparser/pre_parser.mly`)
- Lexer: `cparser/Lexer.mll`
- Pre-processor messages database: `cparser/pre_parser_messages.ml` (generated by Menhir)
- Elaboration: `cparser/Elab.ml` (hand-written semantic analysis)
- Output: `Cabs.v` (Coq AST) via extraction

**Config File Parser:**
- Lexer: `lib/Readconfig.mll`
- Parses compcert.ini into Machine.config record

**Response File Parser:**
- Lexer: `lib/Responsefile.mll`
- Parses response files for command-line arguments (GNU response file style)

**Tokenizer:**
- Lexer: `lib/Tokenize.mll`
- Utility lexer for code generation and parsing

## JSON Output Integration

**AST Export:**
- Module: `backend/JsonAST.ml`
- Exports compiled program in JSON format (suffix: `.json`)
- Used by: AsmToJSON module for machine-readable dumps
- Includes: Architecture metadata, code blocks, annotations

**Annotation Metadata:**
- Module: `backend/AisAnnot.ml`
- JSON-formatted assembly annotations for debugging/analysis
- Context: Inline annotations for AIS (Advanced Instrumentation System) support

## Module Extraction Points

**From Coq to OCaml:**
- `extraction/extraction.v` - Main extraction file defining all extraction directives
- Extracts: Compiler, parser, color checker, data structures, algorithms
- Architecture-specific: `x86/extractionMachdep.v` for x86-64 specific extractions

**Verification Hooks:**
- `driver/Complements.v` - Top-level theorem `transf_c_program_to_rtl_preservation_faulty` proving fault tolerance
- Main entry: `driver/Compiler.v` - Defines transformation pipeline
- Color oracle axiom: `RTLcolorcheck.infer_coloring` (realized by `backend/RTLinfercolor.ml`)

## Build Artifact Dependencies

**Input Files:**
- `.c` - C source (parsed by Menhir-based front-end)
- `.i` - Preprocessed C
- `.p` - Preprocessed C (alternative extension)
- `.s` - Hand-written assembly
- `.S` - Preprocessed assembly (requires preprocessing)
- `.o` - Object files (from external tools)

**Output Files:**
- Binary executable (ccomp, clightgen, vcomp)
- `.o` - Object files (architecture-specific)
- `.s` - Assembly listing (intermediate or final)
- `.json` - JSON AST dumps
- `.rtl`, `.light.c`, `.cm`, `.ltl`, `.mach`, `.alloctrace` - Intermediate representation dumps
- `libcompcert.a` - Static runtime library
