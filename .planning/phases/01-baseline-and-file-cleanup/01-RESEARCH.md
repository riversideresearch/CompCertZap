## Architecture Patterns

### Build System Structure

```
Makefile                    # Master build file
  BACKEND=...              # Lists all backend .v files (line 159-191)
  FILES=$(VLIB)...         # Union of all .v file lists (line 234)
  check-admitted: $(FILES) # Greps source files for Admitted (line 435)
  proof: $(FILES:.v=.vo)   # Compiles all proofs (line 260)
  %.vo: %.v                # Pattern rule for individual compilation (line 323)

Makefile.config            # Generated by ./configure (already present)
_CoqProject                # Generated, lists -R include paths (already present)
.depend                    # Generated by make depend (NOT present, must be created)
```

### Key Build Dependency: `make depend`

The `.depend` file does not exist. Without it, individual `.vo` targets will fail because Coq cannot resolve inter-module dependencies. The Makefile has:

```makefile
# Line 245: 'all' target auto-generates .depend
all:
	@test -f .depend || $(MAKE) depend
```

But targeted builds like `make backend/Novotesproof.vo` do NOT auto-trigger `depend` -- they rely on `-include .depend` (line 452) which silently skips if the file is missing. This means dependencies won't be tracked and the build may fail or produce incorrect results.

**Action required:** Run `make depend` before any `.vo` builds.

### VPATH Mechanism

The Makefile uses `VPATH=$(DIRS)` (line 126) so that `make backend/RTLtolerant.vo` works -- Make searches the `backend/` directory for `RTLtolerant.v` automatically.

### Pattern: check-admitted Scope

`check-admitted` (line 435-437) greps `$(FILES)`, which is the list of `.v` files registered in the Makefile. It does NOT recursively search directories. This means:
- Untracked backup files with `Admitted` are NOT caught by `make check-admitted`
- But the success criterion's `grep -rn "^\s*Admitted" backend/ driver/` DOES search all files in those directories
- Therefore backup files must be deleted before the directory-level grep passes

### Pattern: Untracked File Deletion Order

Since the directory-level `grep` for `Admitted` fails while backup files exist (they contain active `Admitted.` calls), the deletion step (FILE-01) must precede or coincide with the baseline grep verification. The correct order is:

1. `make depend` (prerequisite for all builds)
2. Build targeted `.vo` files (FILE-04 partial -- proves proofs compile)
3. `make check-admitted` (FILE-04 partial -- passes because it only checks `$(FILES)`)
4. Delete all backup files (FILE-01)
5. Delete AdvSem.v and Replicate3proof.v (FILE-02, FILE-03)
6. `grep -rn "^\s*Admitted" backend/ driver/` (FILE-04 completion -- now passes)
7. Verify `git status` is clean of the 15 files

### Anti-Patterns to Avoid

- **Running targeted .vo builds without `make depend` first:** Builds may appear to succeed but miss dependencies, or fail with cryptic module-not-found errors.
- **Deleting files before verifying no references exist:** Always `rg` for the module name in all tracked `.v` files first. Already verified for this phase -- no references found.
- **Running `make proof` for baseline when only targeted builds are needed:** A full `make proof` compiles ALL ~190 `.v` files and takes significant time. The success criterion only requires 4 specific `.vo` files.

## Common Pitfalls

### Pitfall 1: Missing .depend File
**What goes wrong:** Individual `.vo` builds silently skip dependency tracking, potentially building against stale or missing intermediate `.vo` files.
**Why it happens:** `.depend` is in `.gitignore` and not committed. The `-include .depend` directive (Makefile line 452) silently succeeds even when the file is absent.
**How to avoid:** Always run `make depend` as the first step of any build session on a clean checkout.
**Warning signs:** Mysterious `Error: Cannot find library` during `.vo` compilation.

### Pitfall 2: Confusing check-admitted Scope with Directory Grep
**What goes wrong:** `make check-admitted` passes but there are still `Admitted` proofs in backup files in the `backend/` directory.
**Why it happens:** `check-admitted` only searches `$(FILES)` (Makefile-registered source), not all files on disk.
**How to avoid:** Use both `make check-admitted` AND `grep -rn "^\s*Admitted" backend/ driver/` as the success criterion specifies.
**Warning signs:** Backup files containing `Admitted.` visible in `git status`.

### Pitfall 3: Deleting Files That Are Gitignored vs Untracked
**What goes wrong:** Confusion between `.gitignore`'d build artifacts (`.vo`, `.glob`) and truly untracked backup files.
**Why it happens:** Both show differently in `git status`. Build artifacts are ignored (not shown), backup files are untracked (shown with `??`).
**How to avoid:** Use `git status` (not `git status --ignored`) to see only the untracked files targeted for deletion. All 15 target files show as `??` (untracked).

### Pitfall 4: Build Time Surprises
**What goes wrong:** `make proof` or even targeted builds take much longer than expected.
**Why it happens:** The 4 targeted proof files total ~7500 lines of Coq, and each has transitive dependencies on the entire CompCert frontend pipeline. First build from clean state compiles all dependencies.
**How to avoid:** Use `make -j$(nproc)` for parallelism. Expect the first targeted build to take 10-30 minutes depending on hardware as it compiles all transitive dependencies. Subsequent individual file rebuilds will be fast.

### Pitfall 5: Forgetting RTLinfercolor_unify.ml
**What goes wrong:** The requirement mentions "13 untracked backup files" but there are actually 14 untracked files matching the backup pattern. `RTLinfercolor_unify.ml` has a different naming pattern (no `backup_` prefix) but is functionally a backup.
**How to avoid:** See Open Questions section. The planner should delete all 14 files or explicitly confirm the 13 intended by the requirement.
