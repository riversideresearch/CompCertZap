# Plan: Interface TMR for Function Arguments

## Goal

Extend RTL TMR so selected internal function calls pass protected
arguments as Red/Green/Blue triples.

This is the first stage of interface TMR. It deliberately keeps returns
on the current White-boundary discipline:

- internal protected callees receive tripled arguments
- direct protected call sites pass tripled arguments
- call results are still single White values
- callers still copy call results back to shadows after return
- external, indirect, and non-eligible calls remain White boundaries

## Current Baseline

Today `backend/RTLtmr.v` preserves function signatures and parameter
lists. It creates shadow registers for parameters, then initializes
those shadows in a function prologue.

Calls are also White boundaries:

1. vote the function pointer and argument registers
2. execute one RTL `Icall`
3. copy the single result register into its shadows

The current proof and checker bake this in:

- `RTLtmrspec.match_function` preserves `fn_sig` and `fn_params`
- `RTLtmrspec.match_Icall` votes call arguments
- `RTLcolor.wc_Icall` requires call arguments to be White
- `RTLcolor.wc_function` requires all entry parameters to be White
- `RTLtolerant` relies on those White call arguments to prove
  `Val.lessdef` through `Callstate`

## Design

### Eligible Calls

For the first version, transform only:

- direct internal calls
- whose callee is known at transformation time
- whose callee is selected for the protected-argument ABI
- whose callee is not address-taken, unless wrappers are implemented

Keep these on the old ABI:

- external calls
- indirect calls
- calls to non-eligible internal functions
- calls involving `main`
- calls whose signature contains unsupported argument types

### Transformed Function Interface

For an original function:

```text
f(A1, ..., An) -> R
```

the protected-argument ABI is:

```text
f_arg_tmr(A1_r, A1_g, A1_b, ..., An_r, An_g, An_b) -> R
```

The result type `R` is unchanged.

At RTL, this means:

- `fn_sig.sig_args` is expanded by tripling each original argument type
- `fn_sig.sig_res` is unchanged
- `fn_params` is expanded by replacing each original parameter `p` with
  `p, p_g, p_b`, where `rm # p = (p_g, p_b)`

The original parameter register is the Red channel. The two shadow
registers generated by the TMR pass become the Green and Blue ABI
parameters.

### Function Entry

For protected-argument functions, do not emit the usual prologue copies
for original parameters. Those shadows are initialized directly by
`RTL.init_regs` from the expanded argument list.

The function prologue should still copy any non-parameter live-in
registers that the current TMR pass already handles.

Concretely, the current:

```coq
copy_all_to_shadows re rm (app' live f.(fn_params)) f.(fn_entrypoint)
```

becomes, for protected-argument functions:

```coq
copy_all_to_shadows re rm live f.(fn_entrypoint)
```

where `live` has already excluded original parameters. Non-eligible
functions keep the current behavior.

### Transformed Direct Calls

For a direct call to an eligible callee:

```text
Icall sig (inr id) [a1; ...; an] res succ
```

emit a call with tripled arguments:

```text
Icall sig_arg_tmr (inr id)
  [a1; a1_g; a1_b; ...; an; an_g; an_b]
  res
  copy_result_succ
```

where `rm # ai = (ai_g, ai_b)`.

Do not insert majority votes for those argument registers merely to
cross the call boundary.

After the call, keep the current result handling:

```text
smove_green res res_g;
smove_blue  res res_b;
succ
```

This preserves the current White return boundary.

### Non-Eligible Calls

Non-eligible calls use the existing transformation:

- vote arguments to White
- call the old ABI
- copy the result to shadows

This conservative fallback is required for external and indirect calls.

## Implementation Impact

### `backend/RTLtmr.v`

Add an ABI mode for each internal function:

```text
Old ABI
Protected-argument ABI
```

For protected-argument functions:

1. build the replication map before constructing the target function
2. expand `fn_sig.sig_args`
3. expand `fn_params` using the replication map
4. skip parameter prologue copies
5. transform eligible direct call sites to pass tripled arguments
6. leave call results on the existing copy-to-shadows path

The pass needs a callee eligibility map before transforming instructions.
For the first version, this can be a conservative syntactic analysis.

### `backend/RTLtmrspec.v`

The old spec cannot be weakened in place because it preserves signatures
and parameter lists.

Add new relational cases:

- `match_function_args_tmr`, relating an old function to one with
  expanded arguments and expanded parameters
- `match_Icall_args_tmr`, for direct protected calls with tripled args
- an entry-copy relation that excludes original parameters in the
  protected-argument ABI

Keep the old cases for non-eligible functions and non-eligible calls.

### `backend/RTLtmrproof.v`

The main new proof obligations are:

1. transformed function entry:
   `Callstate stk f args m` matches
   `Callstate tstk tf (triple_args args) m`
2. `exec_function_internal` establishes `match_regsets` directly from
   expanded `fn_params`
3. eligible `exec_Icall` simulates without `maj_vote_regsR` for call
   arguments
4. return and `exec_return` cases remain close to the current proof

The existing `sig_function_translated` lemma must be replaced by an ABI
relation:

```text
funsig tf = transformed_signature mode (funsig f)
```

For non-eligible functions, this relation reduces to equality.

## Color System Impact

### Declarative Rules

Add protected-argument variants of the existing function and call rules.

For protected-argument function entries:

- expanded parameters appear in Red/Green/Blue groups
- each group corresponds to one original source argument

For protected direct calls:

- the callee reference must be direct, or otherwise known eligible by a
  program-level side condition
- argument lists are grouped as Red/Green/Blue triples
- the result is still White at the successor
- non-argument live registers preserve their colors across the call

Keep the current White `wc_Icall` rule for non-eligible calls.

### Checker

The checker can probably remain mostly local, but it needs a way to
recognize protected-argument ABI functions and protected direct calls.

Recommended first option:

- derive the mode from a transformation-produced eligibility map in the
  proof
- keep the extracted checker validating only local color consistency
- add a small program-level proof side condition tying direct call
  targets to callee ABI modes if the local rule is not enough

Avoid a general interprocedural color analysis in the first version.

### Inference Oracle

Update `backend/RTLinfercolor.ml` so that:

- protected-argument `fn_params` groups are initialized as Red, Green,
  Blue
- protected direct call argument groups are colored Red, Green, Blue
- call results remain White
- non-eligible calls keep the current White discipline

## Faulty Simulation Impact

The existing `RTLtolerant` call case uses the White call rule to prove
`Forall2 Val.lessdef` for `rs##args`.

For protected-argument calls, add a stronger call-argument relation:

```text
call_args_match faulted colors source_args faulty_args
```

When no fault has occurred, all corresponding arguments are `lessdef`.
When one fault has occurred, at most the affected color channel may fail
`lessdef`; the other two channels still match.

The `Callstate` match relation then needs to distinguish:

- old ABI calls: ordinary `Forall2 Val.lessdef`
- protected-argument ABI calls: grouped color-aware argument relation

The `exec_function_internal` case must use the callee entry parameter
colors to convert the grouped argument relation into the ordinary
register-state invariant after `init_regs`.

No protected memory invariant is needed for this arguments-only stage.

## Restrictions for the First Milestone

Use all of these unless there is a strong reason not to:

- transform direct internal calls only
- preserve `main`'s external ABI
- leave indirect calls on the current White path
- leave external calls on the current White path
- keep returns on the current White path
- disable protected-argument ABI for address-taken functions unless
  wrappers are implemented
- do not try to support separate compilation or binary interoperability
  beyond conservative wrappers

## Suggested Phases

### Phase 0: ABI Metadata

Define:

- function eligibility
- transformed argument signatures
- transformed parameter lists
- direct-call eligibility

Deliverable: a Coq-level specification of the ABI mode relation.

### Phase 1: Executable Transformation

Modify `RTLtmr.v` to:

1. compute eligibility
2. expand protected function signatures and params
3. initialize parameter shadows from call arguments
4. transform eligible direct calls
5. keep old call handling elsewhere

Deliverable: transformed RTL generation compiles.

### Phase 2: TMR Soundness

Update `RTLtmrspec.v` and `RTLtmrproof.v`.

Deliverable: a replacement `transf_program_correct` theorem for the
arguments-only ABI.

### Phase 3: Color Rules and Checker

Update `RTLcolor.v`, `RTLcolorcheck.v`, and `RTLinfercolor.ml`.

Deliverable: `check_program_sound` holds for the new call/entry rules.

### Phase 4: Faulty Simulation

Update `RTLtolerant.v` call and entry cases.

Deliverable: the existing `faulty_backward_simulation` theorem statement
is restored for programs accepted by the new checker.

### Phase 5: Top-Level Composition

Update `driver/Compiler.v` and `driver/Complements.v` only as needed.

Deliverable: `transf_c_program_to_rtl_preservation_faulty` composes
through the arguments-only TMR pass.

## Exit Criteria

This stage is complete when:

1. eligible direct internal calls pass protected argument triples
2. non-eligible calls still use the old White boundary
3. returns still use the old White boundary
4. TMR soundness is reproved
5. checker soundness is reproved
6. faulty backward simulation is reproved
7. the top-level RTL fault-tolerance theorem is restored

At that point, the return plan can be attempted with a stable protected
argument ABI already in place.
